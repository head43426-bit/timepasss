      04 The method

      how it works.

      detect → connect → explain
      01

      Detect & labelfind the suspicious events · tag each one

      A visible catalogue of 22 rules. Every flagged event shows its MITRE ATT&CK technique, kill-chain stage, confidence, and the plain-words reason naming the word that matched. One failed login never flags brute force — 5+ failures for one user + host in 60 minutes do.

      T1110 Brute ForceT1566.001 SpearphishingT1003.001 LSASS dumpT1053.005 Scheduled taskT1071.001 C2 beaconT1021.002 SMB lateralT1070.001 Clear logsT1041 Exfiltration
      02

      Connect the stepslink across host · user · IP · time

      • Direct — same host / IP within 60 minutes.
      • Credential — same account, up to 48 hours.
      • Host continuity — same computer across a long quiet gap.
      • Credential chain — credentials taken earlier, then used on a new host. This is what links the web-shell hop to the database, where nothing else matches.

      Both windows are visible and adjustable. Unlinked flagged events are counted, not invented into the path.

      03

      Explain & look aheadone narrative · what comes next

      Timeline plus a host-and-user graph, then exactly three sections: where it began, what the attacker did, in order, and which systems they can reach next — each reach with why, and what blocks that move. If no synthetic topology covers a host, no target is guessed.

      05 The engine

      the engine.

      python · duckdb · networkx

      The browser demo above is the story. Underneath it, the full build is a real streaming engine: Python parses line by line and never loads a file whole, DuckDB stores incidents and edges with indexed lookup, and NetworkX rebuilds the path as a graph. Rules live in Sigma-style YAML — a new rule is a config edit, not code.

      Slot 01

      Python · parse

      Reads line by line, in batches. A file is never loaded whole.

      Slot 02

      DuckDB · store

      Incidents, detections and edges, with indexed lookup for one path in milliseconds.

      Slot 03

      NetworkX · link

      Hosts and users as nodes, events as edges — the path rebuilt as a graph.

      Slot 04

      Sigma YAML · rules

      Detection rules as config. Add a rule, restart, detection changes.

      Honest limits, stated in the open.

      Detection is keyword rules plus a severity fallback — a cleverly worded real attack could miss every keyword. Host-continuity and credential-chain links are documented heuristics, not proven identity matches, which is why their kind is shown on every edge. Next-reach guesses come only from the small synthetic topology. MITRE labels are illustrative mappings, not a certified live feed. And the 100% scores are against planted synthetic ground truth — not real-world performance.

      Sarvam was tested in mock mode only (no key). Dockerfile / Compose are written but not run-tested here. No login, cloud deployment, or attack blocking — per the PRD's non-goals.
